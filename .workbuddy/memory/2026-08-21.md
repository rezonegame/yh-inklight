### 关键坑（可复用）
1. **import 注入陷阱**：迁移脚本只在已有 `import` 行之后注入 `import { t }`；若某文件原本零 import（如 `tagDomain.ts`），注入静默跳过，该文件的 `t()` 调用在运行时才 `ReferenceError`——esbuild 不报错（因为 `t` 在 production build 中也被 external 了）。**对策**：迁移后必须逐文件验证 `grep 'import { t }'`。
2. **backtick vs double-quote**：模板字符串用反引号（`` `${tag.name} 图标` ``），但迁移规则的 TEMPLATED 匹配只用了双引号，导致 3 个 aria-label 漏改。**对策**：TEMPLATED 规则需同时覆盖双引号和反引号两种字面量形式。
3. **测试构建与 obsidian 的不兼容**：`obsidian` npm 包是 types-only（`"main": ""`），esbuild 无法 bundle。production 构建通过 `external: ["obsidian"]` 解决，但测试构建不 external。**对策**：用 `alias` 指向最小 shim。
4. **Windows safe-delete**：测试 harness 的 `rm -rf .test-run` 在 Windows 上触发 safe-delete shim 并抛异常，掩盖测试结果。**对策**：用 `try/finally` 包裹 cleanup，或在 grep 输出时过滤 safe-delete 噪音。
